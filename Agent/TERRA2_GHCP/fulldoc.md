## Why the node was not syncing (diagnosis, 2026-09-03)

The pod reported `Running` but produced **zero log output** for 33 minutes and
refused connections on 26657. Four distinct defects, found by measurement:

| # | Defect | Evidence |
|---|--------|----------|
| 1 | **`terrad` 2.12.4 cannot follow phoenix-1.** `terra-money/core` is abandoned — `main` frozen 2024-03-07, tags stop at 2.12.4, upgrade handlers only reach v2.10. | `curl https://terra-rpc.polkachu.com/abci_info` returns app version **`v2.20.0`**. | 2 | **`03-statefulset.yaml` had never been applied successfully.** A stray paste had welded shell text onto the `configure` image line: `image: curlimages/curl:8.10.1          terrad export --home /app ...`. | YAML parsed that as the *image name*. | 3 | **The StatefulSet silently refused to roll.** `podManagementPolicy: OrderedReady` will not replace a pod that has never become Ready — and this pod never passed its startup probe. | 4 | **No explicit entrypoint.** The manifest relied on the old image's `CMD ["terrad","--home","/app","start"]`. Alpine has no such CMD. | Verified via the GHCR config blob. |

### The genesis trap that was *avoided*

phoenix-1's original genesis is **747,446,522 bytes** (`genesis_time 2022-05-28`).
The manifest instead installs a **7,988-byte stub** (`genesis_time 2023-08-10`)
from Polkachu. That looks wrong, and replacing it would have broken the node.

Both `terra-rpc.polkachu.com` and `terra-rpc.publicnode.com` return
`total: 1` from `/genesis_chunked?chunk=0` and serve the **stub** — the entire
operating network runs it. CometBFT 0.38 stores the genesis hash in `state.db`
and compares it on every subsequent start, so a snapshot restored from Polkachu
carries the *stub's* hash. Installing the "official" 747 MB file would fail with:

```
genesis doc hash in db does not match loaded genesis doc
```

**Keep the stub.** It is the correct genesis for this snapshot.

Four init containers get the node caught up in ~20–60 minutes (dominated by the snapshot download):


| # | Container | What it does |

### 2.5 External P2P — firewall port-enable (only if inbound peers are needed)


The compose sets `PUBLIC_ADDRESS=13.86.34.113:26656`, which means the VM was

**internal** (private VNet IP), so no inbound peer can reach it.


If NextGen decide they want the archive node to also serve peers:
1. Raise a DevOps port-enable request for TCP `26656`.
2. Once approved, either add an Azure Firewall DNAT rule from the public IP to

**Do neither of these without written firewall approval.** Outbound peering
already works from the pod's egress path, and the archive node will sync fine
without inbound peers.

## 4b. RPC Verification — proving the node actually works


`kubectl get pods` showing `Running 1/1` proves almost nothing. A node can be
Running, Ready, and syncing nothing. These checks go from "is the process
alive" to "is it serving real chain data".


On Windows, write **`curl.exe`** — bare `curl` is a PowerShell alias for
`Invoke-WebRequest`.


### Step 1 — Is the process alive?
```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- wget -qO- http://localhost:26657/health
```
Expect `{"jsonrpc":"2.0","id":-1,"result":{}}`. Note: CometBFT's `/health`
returns `{}` unconditionally — it does not prove sync, only that the RPC
process is answering.


### Step 2 — Right chain, right version?
```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- wget -qO- http://localhost:26657/abci_info
```
Expect `"data":"terra"` (or similar Terra ABCI name) and a `version` matching
the live `phoenix-1` consensus version. Compare with a public node:
```bash
curl.exe -s https://terra-rpc.polkachu.com/abci_info
```


### Step 3 — Connected to the network?
```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- sh -c "wget -qO- http://localhost:26657/net_info | head -c 200"
```
Read `n_peers`. **Zero peers means it can never sync** — check egress on
TCP 26656. The `PERSISTENT_PEERS` list from the compose file is what keeps the
peer count stable.


### Step 4 — Is it actually advancing? *(the one that matters)*
```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- wget -qO- http://localhost:26657/abci_info
```
Run it, wait 60s, run again. Compare `last_block_height`.


| Delta over ~60s | Meaning |
|---|---|
| **> 60** | Catching up healthily |
| **~12** | At the tip — done |
| **0** | Stalled. Same height *and* same `last_block_app_hash` confirms it. |


### Step 5 — How far behind?
```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- sh -c "wget -qO- http://localhost:26657/status | head -c 900"
curl.exe -s https://terra-rpc.polkachu.com/status
```
Compare `sync_info.latest_block_height` on each. `catching_up` flips to
`false` at the tip.


### Step 6 — Is the APP layer serving, not just consensus?
```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- wget -qO- http://localhost:1317/cosmos/base/tendermint/v1beta1/syncing
```
`{"syncing":false}` = the REST API on 1317 is up **and** the node reports
itself synced.


```bash
kubectl exec -n terra2 node-terra2-0 -c terra -- sh -c "wget -qO- http://localhost:1317/cosmos/bank/v1beta1/supply | head -c 200"
```
Returns the `uluna` total supply. Proves the ABCI application is genuinely
queryable — state is readable, not just blocks arriving.


### Step 7 — Historical queries (proves the archive data is intact)
```bash
# Terra 2.0 launched at height 1. An archive node MUST answer height=1:
kubectl exec -n terra2 node-terra2-0 -c terra -- sh -c "wget -qO- 'http://localhost:26657/block?height=1' | head -c 300"
```
This is the archive-node acceptance test. A pruned node would return
`requested block height … is not available`. An archive node must return the
block header.


### Step 8 — From outside the cluster, through the Internal LB
```bash
kubectl get svc node-terra2-rpc-lb -n terra2 -o jsonpath='{.status.loadBalancer.ingress[0].ip}'
```
Then, from anything on the VNet:
```bash
curl.exe -s http://<ILB-IP>:26657/status                                        # Tendermint RPC
curl.exe -s http://<ILB-IP>:1317/cosmos/base/tendermint/v1beta1/syncing         # REST
# gRPC on 9090 needs grpcurl:
grpcurl -plaintext <ILB-IP>:9090 cosmos.base.tendermint.v1beta1.Service/GetLatestBlock
```

## 8. Notes and Known Gotchas


1. **PUBLIC_ADDRESS is intentionally cleared.** The compose set
   `13.86.34.113:26656`, but the AKS P2P LB is internal by default and cannot
   receive that traffic. The `configure` init container sets
   `external_address = ""` in `config.toml` so terrad advertises whatever
   address it can actually bind — advertising an unreachable public IP gets
   the node deprioritised and dropped by peers. If external P2P is later
   approved via the firewall port-enable request (§2.5), set
   `external_address` to the ILB IP (or the DNAT'd public IP) and roll the
   StatefulSet.
2. **Cosmovisor auto-upgrades are no longer active** — the upstream image
   ships terrad directly, not Cosmovisor. Chain upgrades are handled with
   bumping `VER`+`SHA` in the `install-terrad` init container.
   Track [phoenix-directive/core releases](https://github.com/phoenix-directive/core/releases)
   and mainnet governance and roll the tag before each upgrade height.
3. **Archive disks grow.** Currently Terra 2.0 mainnet archive is ~2 TB.
   pvc-watcher will expand up to `MAX_SIZE_GI=3000`; increase that limit and
   patch the ConfigMap before the disk hits 2.4 TB to give the watcher runway.
4. **`ulimits.nofile: 65535` is not portable.** The compose file requested
   65535 open files. In AKS, this is controlled by the node pool kubelet
   config, not the pod spec. If Terra hits the fd ceiling (unusual for a
   Cosmos node), work with the AKS platform team to adjust the node pool
   `maxOpenFiles` — do not try to set it here.
5. **Egress from AKS.** The node pulls `alpine:3.19` / `curlimages/curl` and
   does not require an `imagePullSecret`. If pulls ever fail with `unauthorized`
   or `denied`, the fault is typically an egress/proxy issue on the AKS node
   pool, not authentication. Verify with
   `kubectl run gh-probe --rm -it --image=alpine:3.19 --restart=Never -- wget -S -O- https://ghcr.io/v2/`.
